# Web QA - 2026-10-03

## Environment

- Served the release build from an isolated temporary directory under `/savemed/` at localhost; no Hostinger or API changes were made.
- Microsoft Edge, SaveMed bundle candidate `main.6fd80cd39642b7f78c8244e55d42f3cff9e7b7be0bbc3ef3e0faae18c990104b.dart.js`.

## Results

- Login rendered and its accessible controls were exposed. The registration action opened the customer form without sending data.
- At CSS viewport 390x844, `window.innerWidth`, `document.documentElement.scrollWidth`, and `document.body.scrollWidth` were all 390. At 1440x900, all three were 1440. No horizontal overflow was measured at either size.
- The settled accessibility tree exposed only the active registration form, not the outgoing login controls.
- The password confirmation field bounds (`x=37, y=734, 323x53`) and the version label bounds (`x=336, y=1193, 27x15`) did not overlap at 390x844.
- With a synthetic QA password in the first field and the confirmation empty, the length requirement showed as met, the match requirement remained pending, and the mismatch error was absent. A different confirmation showed the mismatch error and an unmet match requirement; replacing it with the same synthetic value cleared the error and changed both indicators to met. Automated Flutter tests cover these three states too.
- Screenshot capture through the browser backend timed out during the original responsive check. A later preview capture succeeded for the password feedback state; the responsive measurements remain supported by the accessibility tree and DOM geometry checks at 390x844 and 1440x900.
- Only synthetic QA password values were entered locally; no real credentials, personal data, or pharmacy data were entered, and signup was never submitted.

The AVD check is documented separately in [Android QA](android-qa-2026-10-03.md).
